# Пакет навигации по Test Run — r1

Дата: 2026-10-08. Основа: пункты RN1–RN2 в `plans/roadmap-solutions-r1.md` и текущая реализация detail run. Эта точная ревизия r1 была явно согласована пользователем и реализована; статус обновлён после коммита кода и документации.

## Результат

Во время выполнения run тестировщик видит группы результатов по полному пути секции, включая родительские папки, и может перейти к нужной группе из навигации. Иерархия и порядок сохраняются в snapshot run, поэтому последующее переименование, перенос или удаление секций не меняет уже созданную историю.

## Наблюдаемое текущее состояние

- `testRunDetailComponent.vue` уже группирует результаты по непосредственной `testcase.section`, но не использует родителей секции.
- `TestRunService._build_case_snapshot()` сохраняет только `{id, name}` текущей секции; `SectionModel` поддерживает `parent` и `sort`.
- `Next not run` прокручивает страницу к ближайшему невыполненному результату; общего перехода к группам нет.
- `TestRunService.preview()` и `create()` используют hash snapshot выбора, что позволяет включить путь/порядок в проверку устаревшего preview.
- Snapshot хранится в JSON результатов; для новых свойств отдельная SQL-миграция не требуется.

## Объём

1. При построении preview и создании run получить для каждой выбранной testcase цепочку её секций до корневой секции. Сохранить в testcase snapshot `section_path` в порядке root→leaf; каждый элемент содержит `id`, `name` и `sort`. Сохранить также `suite_id` и `suite_name`, чтобы одинаковые пути в разных suites не смешивались. Для кейса без секции использовать пустой путь и группу `Default` внутри его suite.
2. Включить suite и `section_path` в selection hash и preview response. Существующие поля `section: {id, name}` и остальные поля контракта не удалять. Preview и результат run должны использовать один и тот же вычисленный путь.
3. В detail run отдавать `section_path` для snapshot-результатов. Для legacy-результатов без snapshot использовать доступный текущий путь, но сохранить `is_snapshot: false`; если родительский путь уже нельзя восстановить, показывать известную секцию или Default без выдуманных родителей. MCP `get_run_results` использует тот же serializer и получает те же поля.
4. Сгруппировать UI по suite и полному пути секций, с детерминированной сортировкой по `sort` из пути. Заголовок группы показывает путь, а кейс входит ровно в одну конечную группу. Учитывать текущий фильтр результатов: пустые группы не показывать, счётчики пересчитывать по видимым результатам.
5. Добавить навигацию по группам в стиле списка секций Suite: на широком экране — компактный список рядом с результатами; на узком — горизонтально прокручиваемый список кнопок. В каждой записи показывать путь/имя и число видимых результатов. Переход прокручивает заголовок группы в область просмотра и передаёт ему фокус для клавиатурной доступности. `Next not run` остаётся доступен и не конфликтует с навигацией.
6. Обновить `project-docs/docs/` для схемы snapshot/preview и поведения группировки, а также отметить RN1/RN2 в `ROADMAP.md` и плане r1 после реализации.

## Приёмка

- Новые preview/create snapshots содержат root→leaf путь секции, порядок и suite; путь одинаков между preview и созданным run при неизменных данных.
- Изменение имени/родителя/порядка/удаление секции после создания не меняет путь в snapshot run.
- Кейсы из одинаково названных путей разных suites отображаются в отдельных группах; кейсы без секции идут в `Default` своей suite.
- Старые snapshot и legacy результаты отображаются без ошибки и без выдуманных родителей; исторический snapshot не подменяется текущим путём.
- Фильтр результатов согласован с группами и счётчиками; фильтрация не оставляет пустые группы или неработающие переходы.
- Навигация работает указателем и клавиатурой, прокручивает к группе, передаёт фокус её заголовку; layout пригоден для узкого viewport.
- REST preview/detail и MCP run result чтение сохраняют обратную совместимость: новые поля только добавляются, существующий формат `section` остаётся.

## Вне объёма

- Изменение структуры `SectionModel`, CRUD секций или перенос кейсов.
- Автоматическое выделение текущей группы при ручной прокрутке через observer.
- Новый endpoint только для навигации и новая SQL-миграция.
- Переработка фильтров статусов, действий с результатами и дизайна Suite.
- Выполнение автоматических тестов, браузерного сценария, Docker или миграций. В текущих project instructions тесты запускаются только по запросу пользователя.

## Риски и ограничения

- Preview hash станет учитывать секционный путь: перенос/переименование секции между preview и create должен приводить к `409` и требовать обновить preview.
- Legacy runs не имеют неизменяемого snapshot; где исходную иерархию восстановить нельзя, UI явно использует только доступную legacy-информацию.
- План не меняет API существующих полей и не требует schema migration; новые поля в JSON snapshots должны быть optional при чтении старых записей.
