# Suite Case Filter Package — r1

Дата: 2026-10-08. Основа: SU2 из `plans/roadmap-solutions-r1.md`, `SuiteCasesPanel.vue` и `useTestSuiteDetail.js`. Это точная ревизия; реализация требует явного согласования пользователя именно для r1.

## Цель

Сделать предсказуемым поиск тест-кейсов в detail suite: пользователь видит только кейсы выбранной секции (включая виртуальную `Default`) и понимает, когда нет кейсов, когда нет совпадений и когда не удалось загрузить список.

## Решение по области поиска

- Поиск ограничен текущей выбранной секцией. Для `Default` фильтруются только кейсы без section.
- Ищем без учёта регистра по названию и short name; пробелы по краям запроса игнорируются.
- При смене секции введённый запрос сохраняется и применяется к новой секции; очистка clearable-поля сбрасывает запрос, даже если Vuetify передаёт `null`.
- Поиск по всей suite и переход к кейсу из другой секции не входят в эту ревизию.

## Объём

1. Явно подписать поле как поиск в выбранной секции и поддержать ввод, очистку, пустой запрос и смену секции.
2. Счётчик рядом с названием секции всегда показывает количество видимых совпадений после фильтра.
3. Разделить состояния: секция не содержит кейсов; кейсы есть, но фильтр не нашёл совпадений; запрос списка завершился ошибкой. Для ошибки предоставить повтор загрузки.
4. Защитить результат списка от гонки запросов при быстрых переключениях секции — поздний ответ старой секции не меняет новый список.
5. Обновить соответствующие `project-docs/docs/`, `ROADMAP.md` и статус SU2 в `plans/roadmap-solutions-r1.md` после реализации.

## Приёмка

- Поиск работает по title и short name независимо от регистра и пробелов по краям.
- Очистка поля, включая `null` от clearable input, возвращает все кейсы выбранной секции.
- При переходе между секциями сохраняемый запрос применяется к новой секции; счётчик и результаты совпадают.
- `Default` включает только unassigned cases; результаты не включают кейсы других секций.
- Для пустой секции, отсутствия совпадений и ошибки сети отображаются разные сообщения; retry повторяет загрузку текущей секции.
- Быстрый переход между двумя секциями не позволяет позднему ответу старого запроса перезаписать текущий список.
- Backend/API/MCP и схема БД не меняются.

## Вне объёма

- Поиск по всей suite или space, серверный полнотекстовый поиск и пагинация кейсов.
- Изменение маршрутизации или split workspace SU1/SU3.
- Изменение критериев поиска существующих кейсов в диалоге Add Existing.

## Проверка

- ESLint затронутых компонентов и production build.
- Browser-сценарий ввода/очистки, смены секции, пустого результата и ошибки сети, если доступен тестовый backend; Docker и миграции не требуются.

## Согласование

Эта ревизия включает только SU2 и фиксирует поиск внутри выбранной секции. Требуется явное подтверждение пользователя для `plans/suite-case-filter-package-r1.md`, revision r1.
