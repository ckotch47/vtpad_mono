# Пакет Run Detail UI Polish — r2

Дата: 2026-10-09. Продолжает `plans/run-detail-ui-polish-package-r1.md` после пользовательского просмотра текущего UI. r1 уже реализовал sticky-навигацию и базовую сводку; r2 уточняет их визуальную иерархию и поведение на длинной странице. API, формулы, значения и бизнес-логику не меняет.

## Цель

Сделать группы Run заметными, аккуратно иерархичными и постоянно доступными слева на desktop. Перестроить сводку так, чтобы прогресс читался первым, а статусы и длительности — как связанные вторичные данные.

## Объём

1. В `testRunDetailComponent.vue` оформить левую панель как самостоятельный навигационный rail: ясный заголовок и счётчик групп, визуально различимые suite и конечная группа/путь, читаемые сокращённые длинные имена с полным accessible label, единый hover/focus/current style и компактные count badges. Сохранить порядок, группировку, фильтры и названия в доступном тексте.
2. Закрепить rail слева на всём длинном desktop scroll в пределах viewport: sticky top offset учитывает app/header/actions, rail получает собственную вертикальную прокрутку при нехватке высоты, выбранный пункт и текущая группа различимы. Проверить, что layout/overflow предков не ограничивает sticky. На mobile сохранить горизонтальную навигацию без overflow страницы.
3. Пересобрать `RunStatsPanel.vue` в цельную сводку: главный компактный блок показывает прогресс (число завершённых, процент, progress bar); распределение статусов оформлено как единая строка/набор цветных индикаторов и чисел, а не равные карточки; время кейсов и общий таймер визуально объединены в секцию измерений с ясными подписями и вторичным порядком показателей. Наиболее полезные значения остаются читаемыми при первом взгляде.
4. Сохранить все существующие значения, формулы, состояния таймера и различие `NULL`/0. Не показывать неизвестное время как ноль; для `untracked`, `running`, `paused`, `completed` показывать понятные статус и длительности. Не добавить автообновление/цикл таймера.
5. Сохранить глубокие ссылки на результат, переход к группе мышью и клавиатурой, видимый focus, фильтрацию и пересчёт количества видимых результатов. Не менять мобильный принцип навигации.
6. Обновить `project-docs/docs/` по пользовательскому поведению Run и отметить polish в `ROADMAP.md` только после реализации и приёмки.

## Приёмка

- На desktop при длинной странице rail остаётся слева в viewport во время прокрутки результатов; его внутренний список прокручивается отдельно и доступен до последней группы.
- Верхняя часть rail не закрыта app/header/actions; sticky работает при фактической структуре overflow-контейнеров страницы.
- Suite и вложенные группы визуально различаются; длинные подписи не ломают ширину, screen reader получает полные имена, счётчики совпадают с видимыми результатами после фильтра.
- Сводка имеет один визуальный фокус на прогрессе, статусы связаны с ним компактно, временные показатели сгруппированы и читаемы; не создаётся горизонтальная прокрутка страницы.
- Ранее поддерживаемые состояния таймера и комбинации полных/частичных/нулевых/неизвестных длительностей показывают те же API-значения и формулы.
- Desktop и mobile browser smoke проверяют sticky scroll, прокрутку списка rail, переходы и отсутствие переполнения; frontend lint/build и `git diff --check` проходят.

## Вне объёма

- API, модели, миграции, MCP/REST контракты, формулы и статусы.
- Новые метрики/аналитика, дополнительные фильтры или поиск групп.
- Другие экраны Run, suites или общий app layout.

Длинные подписи сокращаются визуально, полный accessible label сохраняется; активная группа синхронизируется с прокруткой через scroll event + `requestAnimationFrame`, без опросного цикла.

- Изменены только клиентское отображение, прокрутка и документация; API, вычисления времени, таймерные состояния, REST/MCP контракты и отсутствие фонового polling сохранены.
