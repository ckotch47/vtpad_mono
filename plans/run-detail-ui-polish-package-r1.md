# Пакет Run Detail UI Polish — r1

Дата: 2026-10-08. Основа — пользовательское пожелание: сделать группы результатов визуально аккуратнее, постоянно держать навигацию групп слева и органичнее оформить сводку Run. Это дополнение к уже реализованному `plans/run-navigation-package-r1.md`; не меняет API и метрики.

## Цель

Улучшить обзор длинного run detail: пользователь видит компактную сводку, может быстро прыгнуть к любой группе, а список групп остаётся доступен слева при прокрутке результатов.

## Объём

1. В `testRunDetailComponent.vue` оставить группировку по suite и полному пути секций, но оформить группы как согласованную навигацию: различимые suite/section уровни, понятные сокращённые подписи с полным accessible label, видимый count chip и аккуратное состояние hover/focus/current target. Не менять порядок результатов, фильтры и содержание групп.
2. Для desktop держать панель групп в левой колонке рядом с результатами (`position: sticky`); она остаётся в viewport при прокрутке списка и имеет собственную вертикальную прокрутку, когда групп больше доступной высоты. Учитывать высоту шапки и верхних действий, чтобы панель не перекрывалась fixed/sticky элементами. Sticky действует начиная с текущего desktop breakpoint; на узком экране навигация остаётся компактной горизонтальной и доступной без горизонтального скролла всей страницы.
3. Переработать `RunStatsPanel.vue`, сохранив все существующие значения и формулы. В верхнем уровне показать сводный прогресс и статусы результатов; отдельно сгруппировать измеренное время кейсов с measured/unmeasured counts и таймер run (active/paused/calendar). Сократить ощущение набора из двенадцати одинаковых карточек; второстепенные длительности и счётчики визуально подчинить итоговым показателям. Не показывать длительность как ноль при `NULL`; сохранить различие untracked timer и измеренного нуля.
4. Сохранить переход навигации с указателя и клавиатуры: заголовок группы получает focus и не прячется за sticky header. `Next not run` и фильтры продолжают работать с существующими вычислениями.
5. Не добавлять новую метрику, observer, endpoint, migration, зависимость или глобальный layout. Обновить `project-docs/docs/` и отметить доп. полировку run detail в `ROADMAP.md` только после приемки.

## Приёмка

- При длинном Run на desktop левая панель остаётся слева и внутри viewport, её список прокручивается независимо от результатов; ни один пункт не закрыт header/action bar.
- Группы визуально отражают suite и вложенный путь, счётчики совпадают с видимыми результатами после фильтра; группы без результатов отсутствуют.
- Tab/Enter и переход к группе прокручивают к читаемому заголовку; keyboard focus отчётливо виден и не перекрыт sticky UI.
- На mobile навигация не фиксируется слева, доступна горизонтальными кнопками без переполнения ширины документа; сводка не создаёт горизонтального скролла.
- Значения summary после UI-переработки равны прежним API/расчётам для run с полными, частично измеренными, нулевыми и неизвестными длительностями; active, paused, completed, timer-untracked состояния читаемы.
- Backend compile/runtime контракт не менялся; frontend lint, production build и браузерный smoke desktop/mobile проходят; `git diff --check` чист.

## Вне объёма

- Изменение API, snapshot, статусов, формул времени и run filtering.
- Sticky-поведение списка suites на отдельной странице suites.
- Аналитика дефектов DD1–DD3 и изменение dashboard.
- Автоматическое выделение текущей группы через IntersectionObserver.

## Статус

Реализован по r1. Frontend lint и production build прошли; browser smoke проверил длинный run на desktop/mobile, переход к result, sticky-навигацию после прокрутки, отсутствие горизонтального переполнения и сохранность метрик. Во время browser smoke найден и исправлен недостающий stretch у desktop grid column; валидация повторена после исправления.
