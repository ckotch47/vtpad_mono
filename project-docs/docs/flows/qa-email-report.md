# Отправка QA-отчёта по email

1. Пользователь открывает QA-отчёт в выбранном space и задаёт период и автора багов.
2. Кнопка Email report запрашивает серверный список адресатов. В нём только пользователи с явным членством в этом space, активной компанией и непустым email.
3. Пользователь выбирает до 10 адресатов и поля из фиксированного allowlist. Сервер повторно проверяет доступ к space, период (не более 366 дней), число строк (до 500 в каждой секции) и размер snapshot (до 256 KiB).
4. Preview сохраняет неизменяемый серверный snapshot на 24 часа. Предпросмотр и все последующие письма читают один и тот же snapshot. Истёкшие снимки удаляются пакетами до следующих preview и при попытке отправить истёкший снимок; при полном бездействии приложения удаление отложено до следующего вызова.
5. Перед отправкой пользователь видит период из snapshot, адреса каждого получателя и выбранные поля, затем отмечает явное подтверждение. Клиент передаёт подтверждённые адреса как условие отправки; сервер сравнивает их с текущими адресами и отклоняет запрос, если email изменился. Адрес назначения всегда берётся из БД.
6. REST и MCP повторно проверяют sender permission и актуальное членство адресатов. Отправка выполняется вручную и синхронно; каждому адресату отправляется отдельное письмо без общих To/CC.
7. База резервирует одну запись доставки на комбинацию space, отправителя, idempotency key и адресата. Интерфейс повторяет запрос с тем же ключом после сетевой ошибки; изменение снимка или адресатов создаёт новую операцию. Повтор того же запроса возвращает прежние статусы; использование ключа с другим содержимым отклоняется. При неопределённом результате SMTP повторная отправка с тем же ключом не выполняется.

Для отключённой почтовой конфигурации endpoint отправки возвращает `503`. В логах не сохраняются email адресатов, report payload или исходная ошибка SMTP. Неуспешная доставка отражается только кодом `delivery_failed`.
