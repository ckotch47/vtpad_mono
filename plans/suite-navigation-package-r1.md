# Suite Navigation Package — r1

Дата: 2026-10-08. Основа: SU1 и SU3 из `plans/roadmap-solutions-r1.md`, текущие страницы списка и detail suites, а также Tech Docs sidebar. Эта ревизия точно ограничивает UX и URL поведение; реализация требует явного согласования пользователя именно для r1.

## Цель

В пространстве suites пользователь видит навигацию слева и содержимое выбранной suite на той же странице. Выбор suite отражается в URL, поэтому прямые ссылки и Back/Forward продолжают работать. На телефоне одновременно показывается только список или detail.

## Решение по навигации

- Использовать плоский список suites с поиском, статусом и счётчиком кейсов/секций, визуально оформленный как навигационная панель Tech Docs.
- Не добавлять вложенность suites: у `TestSuiteModel` нет parent, а запрос не требует новой иерархии данных. Дерево секций остаётся внутри выбранной suite.
- Список остаётся серверно-пагинируемым и сохраняет текущие поиск, фильтр статуса, сортировку, создание, редактирование и удаление.

## Объём

1. Объединить страницы `/space/:spaceId/test-suites` и `/space/:spaceId/test-suites/:suiteId` на общем split-layout: список слева, detail справа.
2. Повторно использовать `TestSuiteDetailComponent` и существующие API; не дублировать CRUD кейсов, секций, статистики и запуска.
3. Сохранить URL `/test-suites/:suiteId` как прямую ссылку. При выборе suite менять route; при Back/Forward выбранная suite должна обновляться из route. Переход на `/test-suites` сбрасывает selection и показывает пустое состояние выбора.
4. При неизвестном или недоступном `suiteId` показать штатное состояние ошибки detail и оставить список пригодным для навигации.
5. На desktop/tablet список занимает устойчивую левую колонку, detail использует оставшееся место. На узком viewport показывать либо список, либо detail; в detail есть доступный переход назад к списку, а Back браузера возвращает к предыдущему выбранному состоянию.
6. Обеспечить клавиатурный выбор suites, видимый focus, активное состояние выбранной строки, loading/empty/error состояния списка и корректную ширину длинных названий.
7. Обновить `project-docs/docs/` по UX и маршрутам и отметить SU1/SU3 в `ROADMAP.md` и `plans/roadmap-solutions-r1.md` после завершения реализации.

## Приёмка

- `/test-suites` открывается без выбранной suite; выбор строки открывает её detail в правой панели и обновляет URL.
- Прямая ссылка на `/:suiteId` открывает тот же split-layout с выбранной suite.
- Выбор другой suite, Back и Forward синхронизируют route и отображаемое detail без устаревшего содержимого.
- Существующие фильтры/пагинация списка и действия CRUD работают из левой панели.
- На мобильной ширине пользователь может перейти из списка к detail и вернуться; панели не требуют горизонтального скролла.
- Клавиатурный фокус и выбранное состояние различимы; пустой список, загрузка и ошибка не блокируют навигацию.
- Никакой миграции или изменения REST/MCP контракта не требуется; тестовые suites не получают вложенную структуру.

## Вне объёма

- Вложенность, перенос, сортировка drag-and-drop или новый backend/API для suites.
- Переработка кейсов, фильтра результатов, секций внутри suite либо структуры тест-кейсов/чеклистов.
- Изменение семантики поиска/фильтра в кейсах; это остаётся отдельным SU2 пакетом.
- Автоматические тесты, Docker runtime и ручной браузерный smoke-сценарий входят в проверку только в объёме, который явно разрешён пользователем.

## Риски и допущения

- Повторное использование detail компонента может предполагать текущую ширину и собственный заголовок; при необходимости layout должен адаптировать оболочку без переписывания доменных действий.
- Список suites уже серверно-пагинируемый; поиск по серверной странице должен оставаться корректным и не превращаться в клиентское усечение.
- На мобильном URL остаётся источником выбранной suite, чтобы refresh и прямые ссылки не теряли состояние.

## Согласование

Эта ревизия включает SU1 и SU3 с выбранной плоской навигацией. Требуется явное подтверждение пользователя для `plans/suite-navigation-package-r1.md`, revision r1; после него изменения будут выполняться малыми коммитами с проверкой.
